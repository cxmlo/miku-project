# F-24 · Instalador Ligero de Windows y Actualizador Verificado por SHA-256 (Paso 5.4)

## 1. Objetivo
Empaquetar Miku en un único ejecutable nativo ligero (`miku.exe`, `< 15 MB`) con perfil `release` optimizado (`opt-level = 3`, `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`), instalación sin privilegios de administrador en espacio de usuario, desinstalación limpia con pregunta explícita sobre el borrado de datos y un actualizador fail-closed que **jamás descarga ni ejecuta sin consentimiento explícito y validación SHA-256 exacta**.

## 2. Perfil de Compilación Release (`miku/Cargo.toml`)
```toml
[profile.release]
opt-level = 3
lto = true
codegen-units = 1
panic = "abort"
strip = true
```

## 3. Distribución en Espacio de Usuario (Windows 10 / Windows 11)
| Componente | Ruta | Notas |
|---|---|---|
| Binario instalado | `%LOCALAPPDATA%\Programs\Miku\miku.exe` | Copia verificada por SHA-256; sin UAC/admin |
| Respaldo de rollback | `%LOCALAPPDATA%\Programs\Miku\miku.exe.prev` | Preservado tras actualización verificada |
| Staging temporal | `%LOCALAPPDATA%\Miku\staging\` | Limpiado de inmediato ante cualquier error de hash o tamaño |
| Datos de usuario (SQLite, bóveda, logs) | `%LOCALAPPDATA%\Miku\` | Solo se purga en desinstalación si el usuario acepta explícitamente |
| Perfil WebView2 | `%LOCALAPPDATA%\miku\webview2` | Aislado por origen `https://miku.local` |
| Inicio automático opcional | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Miku` | Solo con bandera `--autostart`; se elimina al desinstalar |

## 4. Contrato del Instalador y Desinstalador (`miku.exe install` / `miku.exe uninstall`)
1. `miku.exe install [--autostart] [--dry-run] [--json]`
   - Verifica que el binario origen no exceda `15 MB` (`BUDGET_MAX_RELEASE_BINARY_MB`).
   - Copia atómicamente hacia `%LOCALAPPDATA%\Programs\Miku\miku.exe` y comprueba coincidencia SHA-256 origen/destino.
2. `miku.exe uninstall [--purge-data | --keep-data] [--dry-run] [--json]`
   - Elimina `miku.exe`, `.prev` y artefactos en `staging/`, más entrada `HKCU\...\Run\Miku` si existe.
   - Si no se especifica `--purge-data` ni `--keep-data`, pregunta al usuario en TTY si desea borrar `%LOCALAPPDATA%\Miku`; en entornos no interactivos (`stdin` sin TTY) falla de forma segura conservando los datos (`purge_data = false`).

## 5. Actualizador Fail-Closed con Consentimiento Explícito y SHA-256 (`miku.exe update`)
Secuencia invariante implementada en `crates/miku-cli/src/installer_updater.rs`:
1. **Validación del Manifiesto (`ReleaseManifestV1`)**:
   - `artifact_name` debe ser un nombre de archivo simple sin `..`, `/` ni `\`.
   - `download_url` exige esquema `https://` (rechaza `http://`, UNC y rutas arbitrarias en canales remotos).
   - `sha256_hex` exige exactamente 64 caracteres hexadecimales válidos.
   - `size_bytes` debe ser `> 0` y `<= 15 MiB`.
2. **Compuerta de Consentimiento Explícito**:
   - Antes de abrir red, copiar bytes o crear archivos `.staging`, se muestra versión, origen y SHA-256 esperado y se exige consentimiento explícito del usuario (`--yes-consent` explícito o confirmación `y`/`yes` en TTY real).
   - Si no hay consentimiento, aborta inmediatamente (`UpdateError::ConsentDenied`) con **0 bytes descargados** y **0 archivos creados**.
3. **Descarga en Staging + Verificación Criptográfica**:
   - Escribe únicamente en `<staging>/<artifact_name>.staging` verificando tamaño máximo.
   - Calcula `sha256_hex` real del artefacto descargado y lo compara en tiempo constante (`constant_time_token_eq`) contra `manifest.sha256_hex`.
4. **Limpieza Obligatoria ante Divergencia**:
   - Si el SHA-256 o el tamaño difieren, el archivo `.staging` se borra del disco **antes** de devolver `UpdateError::IntegrityMismatch`. El binario activo y su respaldo permanecen intactos.
5. **Intercambio Atómico + Rollback**:
   - Solo tras consentimiento + SHA-256 exacto, respalda el ejecutable previo en `miku.exe.prev` e instala el nuevo binario verificado.

## 6. Firma SmartScreen y Verificación Pública de Release
- En CI de lanzamiento (`.github/workflows/release.yml` o etiqueta `miku-v1.0.0`), publicar `miku.exe` junto a `SHA256SUMS.txt` y manifiesto JSON firmados.
- Si el binario se firma con certificado Authenticode (Microsoft Trusted Signing / EV Code Signing), verificar firma antes del swap con `signtool verify /pa` o `Get-AuthenticodeSignature`.
- Para distribuciones comunitarias sin certificado EV, el usuario siempre puede verificar manualmente en PowerShell:
  ```powershell
  Get-FileHash .\miku.exe -Algorithm SHA256
  ```
