# F-14 — Technical Feed for the Island with Conditional HTTP Caching (`ETag` / `Last-Modified`)

**Micro-step:** `3.11`  
**Status:** `PENDIENTE-LOCAL` (awaiting Windows 11 test execution evidence)  
**Target Crate:** `miku-ui` (`miku/crates/miku-ui/src/feed/`)  
**Related ADRs:** `ADR-005` (Mode C WebView2 Island & `textContent` Sanitization), `ADR-007` (Strict Deny-by-Default Gatekeeper)

---

## 1. Architecture & Feed Sources

`IslandTechFeedController` (`miku_ui::feed`) aggregates developer updates across four source kinds (`TechFeedSourceKind`):
1. **Pull Requests (`PullRequests`):** GitHub PR status and review summaries (`badge = "PR"`).
2. **CI Status (`CiStatus`):** GitHub Actions workflow runs and build conclusions (`badge = "CI"`).
3. **RSS / Atom Feeds (`RssFeed`):** Technical blogs, security advisories, and release feeds (`badge = "RSS"`).
4. **Repository Radar (`RepoRadar`):** Tracked repository tags and releases (`badge = "RADAR"`).

---

## 2. Conditional Caching (`ETag` / `Last-Modified`) & Zero-Wake `304 Not Modified`

1. **Validator Storage (`ConditionalValidators`):**
   - Each registered `source_id` maintains `etag: Option<String>` and `last_modified: Option<String>`.
   - Outbound `FeedHttpRequest` messages automatically populate `if_none_match` and `if_modified_since` when stored validators exist.
2. **Zero Reprocessing & Zero UI Wake on `304 Not Modified`:**
   - When a source responds with HTTP `304 Not Modified`, `IslandTechFeedController` preserves the cached `Vec<TechFeedItem>` for that source without invoking XML/JSON parsers (`reparse_delta == 0`).
   - Merged items are fingerprinted with `sha256_hex`. When no source content changes (`304 Not Modified`), `ui_wake_delta == 0` and `OverviewSceneController::dom_updates_count()` remains untouched.
3. **Validator Update on `200 OK`:**
   - When a source responds with HTTP `200 OK` and parses cleanly, stored `etag` and `last_modified` validators are updated for subsequent requests.

---

## 3. Per-Source Fault Isolation & GitHub Rate-Limit Guard

- **Fault Isolation:** If any RSS or GitHub source times out (`FeedTransportError::Timeout`), fails at the network layer, or returns malformed XML/JSON, `IslandTechFeedController` retains the previously cached valid items for that source, records a secret-sanitized diagnostic (`sanitize_feed_diagnostic`), and continues synchronizing all remaining healthy sources.
- **GitHub `X-RateLimit-Remaining` Guard (`RateLimitState`):**
  - GitHub API responses update `remaining` and `reset_at_ms`.
  - When `remaining == Some(0)` and `now_ms < reset_at_ms`, `sync_all_sources` skips network calls to that source (`rate_limited_skips += 1`) and serves cached items until `now_ms >= reset_at_ms`.

---

## 4. Gaming Mode & Offline Pause/Resume

- Synchronization checks `is_gaming_mode_active()` (linked with `IdleSuspensionCoordinator`) and `is_network_online()`.
- While in Gaming Mode (`FeedPauseReason::GamingModeActive`) or offline (`FeedPauseReason::Offline`), `sync_all_sources` issues `0` network requests, `0` reparses, and `0` UI wakes.
- Upon resuming online and exiting Gaming Mode, synchronization resumes cleanly and deduplicates items by stable `item_id` without losing or duplicating entries.

---

## 5. Island Rendering & Gatekeeper-Authorized Link Opening in Zen Browser

- **Island Rendering (`render_into_island`):** Every feed item is rendered through `sanitize_for_text_content` (`WebViewIpcPayloadV1::DomSafeTextRender` with `csp_enforced: true`), neutralizing any HTML/script tags in titles or summaries.
- **Zen Browser Link Opening (`open_item_in_zen_browser`):**
  1. Verifies the item URL uses `https://`.
  2. Evaluates `GatekeeperEngine::evaluate_request("island_tech_feed", Capability::Browser, &item.url, "zen.exe --new-tab", now_ms)`.
  3. Only on `GatekeeperVerdict::Allow` invokes `ZenBrowserLauncher::open_in_zen_browser` (`zen.exe --new-tab <url>`).
