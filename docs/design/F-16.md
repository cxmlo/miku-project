# F-16 — Push-to-Talk (PTT) & Groq Whisper Speech-to-Text (Micro-step 4.1)

## 1. Resumen Arquitectónico
El micro-paso **4.1** implementa la captura de voz bajo demanda mediante **Push-to-Talk (`Alt+Space`)** con transcripción en la nube a través del endpoint oficial **Groq Speech-to-Text (`POST https://api.groq.com/openai/v1/audio/transcriptions`)**, bajo control estricto de `GatekeeperEngine`, consentimiento explícito del usuario y gestión de secretos exclusivamente por alias (`VoiceSecretAliasStore` / `WindowsCredentialAliasStore`).

> **Declaración explícita de red y facturación (Transparencia Operativa):**
> - **Esta ruta NO es offline, NO es sin red y NO es gratuita.**
> - Cuando el usuario sostiene y suelta `Alt+Space` (superando el umbral de rebote de `120 ms`), el audio capturado se codifica en `RIFF/WAVE PCM 16-bit mono 16 kHz` en memoria volátil y se transmite mediante `HTTPS` (`multipart/form-data`) al proveedor externo **Groq (`api.groq.com`)** para su transcripción.
> - **Modelo de costes de Groq STT:** La facturación se calcula por duración de audio procesado con un **mínimo facturable de 10 segundos por petición** (`GROQ_MIN_BILLED_SECONDS_PER_REQUEST = 10`):
>   - `whisper-large-v3-turbo`: `$0.04 / hora` de audio facturado (`$0.0000111... / s`).
>   - `whisper-large-v3`: `$0.111 / hora` de audio facturado (`$0.0000308... / s`).

## 2. Flujo de Seguridad, Privacidad y Ciclo de Vida de Audio

1. **Idle (`0% CPU`, `0 handles` de micrófono):**
   - Mientras PTT (`Alt+Space`) no está presionado, no existe ningún handle de captura de audio abierto (`active_stream_handles() == 0`) ni hilos de polling activos.
2. **Apertura exclusiva durante Hold (`Alt+Space`):**
   - Al presionar `Alt+Space`, `GatekeeperEngine` evalúa la regla de micrófono (`Capability::ProcessExec` / recurso `"audio:microphone:ptt-stream"`). Si no es `Allow`, falla cerrado (`GatekeeperDenied`) sin abrir dispositivo.
   - Si se suelta antes de `120 ms` (`PTT_MIN_HOLD_MS`), se descarta como rebote accidental (`DebounceRejected`), cerrando el stream y aplicando `secure_zero()` sobre el buffer PCM antes de cualquier llamada de red.
3. **Cierre del micrófono ANTES de transcribir:**
   - En el instante en que el usuario suelta `Alt+Space` (`>= 120 ms`), `PttSttOrchestrator::release_ptt_and_transcribe_to_session` invoca `stop_and_close_stream()` y `zero_fill_pcm_buffer()` en el controlador **antes** de construir o enviar la solicitud HTTP.
   - Queda garantizado por contrato (`mic_closed_before_request == true` y `active_stream_handles() == 0`) que el micrófono jamás permanece abierto durante la latencia de red hacia Groq.
4. **Doble compuerta antes de transmitir audio a la nube:**
   - **Compuerta 1 — Consentimiento explícito (`cloud_audio_consent_granted`):** Si el usuario no otorgó consentimiento explícito para enviar audio a `api.groq.com`, el pipeline aborta con `SttEngineError::CloudAudioConsentRequired`, limpia con ceros el buffer PCM capturado y registra auditoría encadenada.
   - **Compuerta 2 — `GatekeeperEngine` (`Capability::Network` + `secret-manager`):**
     - Verifica `Capability::Network` hacia el recurso `https://api.groq.com/openai/v1/audio/transcriptions` (comando `POST https://api.groq.com/openai/v1/audio/transcriptions`).
     - Verifica autorización de lectura de alias en `secret-manager` (`secret:alias:{api_key_alias}`).
5. **Resolución de API Key exclusivamente por alias (`api_key_alias`):**
   - `GroqSttConfig` almacena únicamente `api_key_alias` (por defecto `"groq-stt-key"`), validado contra inyección de credenciales crudas (`gsk_...`, `sk-...`, `Bearer ...`).
   - En el momento de envío, `VoiceSecretAliasStore::load_secret_by_alias` recupera el secreto desde Windows Credential Manager (`CredReadW` sobre `miku/secrets/{alias}`) o el almacén seguro en memoria (en tests), envolviéndolo en `ZeroizingBytes` (`std::ptr::write_volatile` + `compiler_fence`).
6. **Zero-fill determinista (`ZeroizingBytes` + `VolatilePcmBuffer`):**
   - Los buffers temporales de muestras PCM (`i16`), el contenedor WAV en memoria, el cuerpo `multipart/form-data` y la cabecera `Authorization: Bearer ...` se sobrescriben con ceros volátiles al finalizar con éxito, error HTTP, timeout de red, rebote `< 120 ms`, cancelación con `Escape` o activación de `UiKillSwitchManager::trip`.
7. **Redacción de diagnósticos y logs (`redact_sensitive_voice_diagnostic_with_secrets`):**
   - Ningún error, log o evento de auditoría expone llaves (`gsk_*`, `sk-*`, `Bearer`), bytes de secretos activos, muestras PCM ni el texto transcrito.

## 3. Contrato HTTP con Groq Speech-to-Text (`stt_backends.rs`)

- **Endpoint:** `POST https://api.groq.com/openai/v1/audio/transcriptions`
  - El parser `parse_groq_endpoint` exige `https://` para cualquier host remoto; únicamente permite `http://` cuando el host es loopback (`127.0.0.1`, `localhost`, `::1`) para el servidor de inspección en tests automatizados.
- **Formato de solicitud:** `multipart/form-data; boundary=MikuGroqSttBoundaryV1`
  - `file`: archivo `ptt_capture.wav` (`audio/wav`, `RIFF/WAVE` PCM 16-bit little-endian mono a `16000 Hz`).
  - `model`: `"whisper-large-v3-turbo"` o `"whisper-large-v3"`.
  - `response_format`: `"verbose_json"` o `"json"`.
  - `temperature`: `"0"` (determinismo de decodificación).
  - `language` (opcional): código ISO-639-1 (`"es"`, `"en"`) cuando el perfil del usuario fija idioma, u omitido para detección bilingüe automática.
- **Autenticación:** Cabecera `Authorization: Bearer <secret>` construida en `ZeroizingBytes`.
- **Transporte:**
  - En producción Windows (`https://`): cliente nativo WinHTTP (`winhttp.dll`: `WinHttpOpen`, `WinHttpConnect`, `WinHttpOpenRequest`, `WinHttpSetTimeouts`, `WinHttpSendRequest`, `WinHttpReceiveResponse`, `WinHttpReadData`) sin dependencias externas ni modificación de `Cargo.lock`.
  - En pruebas locales (`http://127.0.0.1:<port>`): `std::net::TcpStream` con timeouts estrictos de lectura y escritura.

## 4. Estructura Modular (`miku/crates/miku-ui/src/voice/`, todos `< 600` líneas)

| Archivo | Responsabilidad |
| :--- | :--- |
| `mod.rs` | Exportaciones públicas del subsistema de voz (F-16). |
| `types_and_buffer.rs` | Tipos base de estado de voz, `VolatilePcmBuffer` (`write_volatile` + `compiler_fence`) y métricas de cancelación (`< 25 ms`). |
| `controller.rs` | `VoiceInteractionController`: ciclo PTT `Idle -> Listening -> Transcribing`, debounce `< 120 ms`, `Escape` y `KillSwitch`. |
| `audit.rs` | `VoiceAuditTrail`: cadena de auditoría FNV-1a inmutable y verificable (`verify_integrity()`). |
| `capture_devices.rs` | `WasapiCaptureDevice` (WASAPI real en Windows + loopback determinista para tests), `AgentPromptQueueBridge` e IPC `voice.transcript.ready`. |
| `stt_engine.rs` | `GroqWhisperModel`, `GroqBillingEstimate`, `GroqSttConfig`, `ZeroizingBytes`, `VoiceSecretAliasStore` (`WindowsCredentialAliasStore` + `InMemoryVoiceSecretVault`) y redacción de diagnósticos. |
| `stt_backends.rs` | Codificador/decodificador `RIFF/WAVE PCM16`, constructor `multipart/form-data`, parser JSON y cliente `GroqWhisperHttpClient` (`WinHTTP` + loopback HTTP). |
| `ptt_pipeline.rs` | `PttSttOrchestrator`: cierre previo de micrófono, verificación de consentimiento cloud, `GatekeeperEngine` (`Network` + `secret-manager`), transcripción y encolado en sesión de agente. |
| `tests.rs` | Suite unitaria original del controlador y benchmark de cancelación (`30 reps < 25 ms`). |
| `tests_ptt_stt.rs` | Suite `LEDGER-4.1-1..7` con servidor HTTP local de inspección (`127.0.0.1:0`) + smoke test opcional (`#[ignore]`) contra Groq real. |

## 5. Estrategia de Verificación (`LEDGER-4.1-1..7`)

Las pruebas automatizadas del workspace **nunca llaman a Groq en vivo ni generan cargos**:
- Levantan un servidor HTTP local efímero en `127.0.0.1:0` (`spawn_local_groq_stt_server`) que inspecciona la petición real enviada por `GroqWhisperHttpClient`:
  - Método `POST` y ruta `/openai/v1/audio/transcriptions`.
  - Cabecera `Authorization: Bearer <secret>` resuelta por alias.
  - Cuerpo `multipart/form-data` con campos `model`, `response_format`, `temperature`, `language` y el archivo `ptt_capture.wav` (`RIFF/WAVE` válido decodificable a muestras PCM).
- Se incluye además el test opcional `test_optional_live_groq_whisper_smoke_when_explicitly_enabled` marcado con `#[ignore]`, que solo se ejecuta si el desarrollador define explícitamente `MIKU_GROQ_LIVE_SMOKE=1` y provee su credencial en el almacén del SO.
