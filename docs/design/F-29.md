# F-29 — Catálogo Declarativo y Bridge Polimórfico de Agentes (`AgentBridge`)

- **Estado:**
  - **Micro-paso 3.5:** VERIFICADO (`miku-agent` catálogo declarativo, trait `AgentBridge`, y adaptadores para Claude Code, Cursor, Antigravity y GitHub)
- **Crate principal:** `miku/crates/miku-agent`
- **Dependencias internas:** `miku-protocol`, `miku-core`, `miku-gatekeeper`, `miku-gateway`
- **Requisitos funcionales:** `F-04` (*Bridge de agentes*), `F-29` (*Catálogo declarativo como única fuente de verdad*)
- **Presupuestos y garantías:**
  - Despacho y renderizado de tarjetas de agentes unificado sin duplicar lógica en UI ni en móvil.
  - Zero polling agresivo: eventos locales y caché condicional `ETag` / `304 Not Modified` para GitHub.
  - Postura conservadora para Google Antigravity: estado tipado `Unsupported` y observación pasiva (sin simular protocolos no confirmados en el repositorio; Spike 0.6 verificó la política de Gatekeeper para 'antigravity').
  - Cero filtraciones de secretos, API keys o tokens de autenticación en tarjetas, logs o errores.

## 2. Catálogo Declarativo Único (`AgentCatalog` & `AgentManifest`)

`AgentCatalog` valida y almacena los metadatos de integración de forma centralizada:

1. **Campos del Manifest:**
   - `id`: Identificador único canónico (`claude-code`, `cursor`, `antigravity`, `github`, etc.).
   - `display_name`: Nombre legible (`Claude Code`, `Cursor IDE`, etc.).
   - `description`: Resumen del propósito del agente.
   - `vendor`: Organización creadora (`Anthropic`, `Anysphere`, `Google`, `GitHub`).
   - `version`: Versión del adaptador / protocolo.
   - `transport`: `AgentTransportKind` (`StdioHook`, `McpHost`, `PassiveLog`, `WebhookRest`).
   - `capabilities`: Lista de capacidades (`shell`, `fs_read`, `fs_write`, `network`).
   - `icon_slug`: Identificador de icono para la pastilla y escena expandida.
   - `is_builtin`: Distintivo de integración del sistema frente a extensiones de usuario.
2. **Validación estricta:**
   - Rechazo inmediato de identificadores vacíos, caracteres no alfanuméricos/guiones, nombres vacíos o IDs duplicados (`CatalogError::DuplicateAgentId`, `CatalogError::InvalidManifest`).
3. **Generación unificada de tarjetas (`render_cards`):**
   - Transforma en una única pasada el catálogo y el mapa de estados en vivo a estructuras `AgentCard`, conteniendo indicadores de ánimo (`working`, `idle`, `thinking`, `offline`, `unsupported`, `error`) listos para el Virtual Host de la Island o el WebSocket de Miku-Link sin requerir bifurcaciones condicionales en el frontend.

## 3. Hallazgos de Spike 0.6 y Adaptadores Específicos

### 3.1 Claude Code (`ClaudeBridge`)
- **Evidencia empírica:** Validado en Spike 0.6 y Micro-pasos 3.1–3.2 con enmarcado JSON-RPC bidireccional sobre stdio, detección de sesiones activas y tolerancia de 15 ms fail-open.
- **Implementación:** Conecta eventos `ToolCall` con `GatekeeperEngine::evaluate_request` bajo precedencia estricta `Deny > Ask > Allow` y emite telemetría de estado (`Active`, `Thinking`, `Idle`).

### 3.2 Cursor IDE (`CursorBridge`)
- **Evidencia empírica:** Validado en Spike 0.6 con intercepción de capacidades no listadas (`NetworkOut -> Default Deny`) y en Micro-paso 3.3 como cliente MCP local.
- **Implementación:** Consume el contrato MCP (`miku-mcp`), canalizando invocaciones de herramientas hacia el Gatekeeper y retornando `GatekeeperDenied` si se viola alguna regla del perfil.

### 3.3 Google Antigravity (`AntigravityBridge`)
- **Evidencia del Spike 0.6:** Spike 0.6 probó que cuando una solicitud se etiqueta con `agent_id = "antigravity"`, el Gatekeeper intercepta y bloquea con éxito escrituras en rutas hostiles (`..\..\Windows\System32\cmd.exe`, escapes UNC, `CON.txt`) mediante `PathJailViolation`. Spike 0.6 **no sondeó ni probó empíricamente la existencia o ausencia de un socket IPC o hooks CLI** en Google Antigravity.
- **Decisión de diseño actual (postura conservadora):** Dado que el repositorio no contiene un protocolo de integración técnica confirmado ni especificaciones de hooks directos, `AntigravityBridge` adopta la postura conservadora de reportar un estado tipado `AgentBridgeStatus::Unsupported` con motivo explícito. Si se intentan llamadas directas a herramientas, devuelve `AgentBridgeError::Unsupported`. No se simulan conexiones falsas ni se inventan APIs; se permite la ingesta de telemetría pasiva de logs y se mantiene en `Unsupported` hasta contar con una prueba técnica de integración confirmada.

### 3.4 GitHub Integration (`GitHubBridge`)
- **Control de Presupuesto:** Garantiza **cero polling agresivo**.
- **Caché Condicional ETag:**
  - Al recibir sincronizaciones periódicas o webhooks con una cabecera `ETag`, compara el valor con `cached_etag`.
  - Si el ETag coincide, responde inmediatamente `AgentBridgeResponse::NotModified { etag }` sin parsear el cuerpo del mensaje, sin asignaciones de memoria redundantes y sin gastar cuota de API (`X-RateLimit-Remaining`).
- **Seguridad y Cero Fugas:**
  - Si se configura un `auth_token` de GitHub (`ghp_...`), la función interna de sanitización redacta cualquier aparición de tokens sensibles en resúmenes de tarjetas, mensajes de error formateados y volcados de depuración.
