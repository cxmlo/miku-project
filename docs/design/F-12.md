# Diseño Técnico · Paso 4.4 (`F-12`): Control de PC por Perfil con UI Automation, Shell Seguro y Kill Switch

- **Estado:** Implementación TDD (`miku/crates/miku-platform/src/pc_control/`)
- **Objetivo:** Exponer de forma segura y auditada las 6 capacidades de control local del PC (`fs_read`, `fs_write`, `shell`, `clipboard`, `ui_automation`, `input`) pasando cada acción por `GatekeeperEngine`, priorizando Windows UI Automation antes que coordenadas de píxeles, blindando comandos shell destructivos mediante una lista `deny` global inamovible y garantizando aborto en `< 20 ms` con el Kill Switch y `0` hilos residentes en reposo.

## 1. Matriz de Capacidades y Prioridad UI Automation
1. **`fs_read` (`Capability::FsRead`) & `fs_write` (`Capability::FsWrite`):** confinamiento obligatorio en la jaula canónica del proyecto (`PathJail`). Cualquier traversal, symlink fuera de raíz, dispositivo reservado DOS o ruta UNC falla cerrado antes de tocar disco.
2. **`shell` (`Capability::Shell`):**
   - **Lista `deny` global inamovible (`IMMUTABLE_SHELL_DENY_PATTERNS`):** patrones destructivos (`rm -rf`, `del /f`, `rmdir /s`, `format `, `diskpart`, `bcdedit`, `cipher /w`, `reg delete`, `vssadmin delete shadows`, `shutdown`, `remove-item -recurse -force`, `iex `, `powershell -enc`, `git reset --hard`, `git push --force`) bloqueados incluso si `.miku.toml` fija `Allow *`.
   - Ejecución directa `(program, args)` sin interpolación `cmd /C` y con `CREATE_NO_WINDOW`.
3. **`clipboard` (`Capability::Clipboard`):** lectura/escritura bajo Gatekeeper usando APIs Win32 Unicode seguras (`OpenClipboard`/`GlobalAlloc`/`GlobalLock`).
4. **`ui_automation` (`Capability::UiAutomation`):** prioriza árbol semántico (`window_title_pattern` + `automation_id_or_name` + `control_type`). El fallback por coordenadas (`UiAutomationFallbackPixelClick`) queda bloqueado si no declara una razón verificada (`ui_tree_unavailable_reason`) de por qué el control no expone UIA.
5. **`input` (`Capability::Input`):** combos de teclado, escritura acotada o clics de respaldo ejecutados paso a paso comprobando `abort_flag` en cada paso (`pc_only` recomendado por perfil).

## 2. Presupuesto de Cero Hilos y Kill Switch `< 20 ms`
- `active_resident_threads() == 0` en reposo; no se crean hilos permanentes esperando acciones.
- `trip_kill_switch`: activa `AtomicBool` (`SeqCst`), revoca todos los tickets en `GatekeeperEngine`, cancela secuencias `input` entre pasos y termina procesos `shell` hijos en `< 20 ms` sin dejar procesos huérfanos.
