# F-10 · Memoria de Largo Plazo en Markdown e Índice Incremental SQLite FTS5

## 1. Objetivo Arquitectónico

Guardar la memoria técnica de largo plazo del proyecto en archivos Markdown (`.md`) legibles y editables por humanos como **única fuente de verdad**, manteniéndolos sincronizados con el índice léxico `memory_fts5` (`miku-storage`) mediante hashes de modificación SHA-256 e inyectando bajo demanda únicamente los fragmentos pertinentes dentro del presupuesto de tokens del turno.

---

## 2. Principios y Restricciones

1. **Fuente de verdad en Markdown (`.md`):**
   - Cada nota vive como archivo `.md` dentro del directorio del proyecto confinado por `CanonicalPathJail`.
   - El índice SQLite FTS5 (`memory_fts5`) es una vista derivada de consulta rápida: si la tabla FTS5 se vacía o reconstruye (`rebuild_fts5_index_from_sources`), el estado completo se regenera determinísticamente a partir de los archivos `.md` en disco y las sesiones persistidas en `SingleThreadStoragePool`.
2. **Sincronización incremental por hash SHA-256:**
   - `MarkdownMemoryVault` registra en `MarkdownNoteMetadata` el `file_sha256` y los `chunk_ids` asociados a cada ruta relativa normalizada.
   - Al ejecutar `sync_markdown_file` o `sync_vault_directory`:
     - Si el SHA-256 del archivo en disco coincide con el registrado, el documento se omite (`skipped_unchanged_files += 1`, **0 operaciones de reindexado**).
     - Si el SHA-256 cambió, se eliminan primero los `chunk_ids` anteriores de `memory_fts5` y `ContextEngine`, y se indexan los nuevos fragmentos semánticos en una sola transacción ACID.
     - Si un archivo `.md` registrado ya no existe en disco, `purge_deleted_note` elimina todos sus fragmentos del índice FTS5 y de la caché para no dejar resultados obsoletos.
3. **Gatekeeper Deny-by-Default (`Capability::FsRead` / `Capability::FsWrite`):**
   - Toda operación de escritura (`write_markdown_note`), lectura/sincronización (`sync_markdown_file`, `sync_vault_directory`) y recuperación (`search_authorized`) evalúa primero `GatekeeperEngine::evaluate_request`.
   - Cuando Gatekeeper deniega o requiere aprobación (`AskPending`), no se realiza ninguna lectura de disco (`disk_reads_performed == 0`) y no se devuelve ningún resultado.
4. **Recuperación Selectiva Bajo Demanda (Cuidado de Tokens):**
   - `retrieve_on_demand_within_budget` evalúa si la consulta del usuario requiere contexto de memoria (`query_requires_memory_lookup`), recupera únicamente el `top_k` autorizado por Gatekeeper y delega en `SystemPromptAssembler::assemble_within_budget` (Paso 1.6 / Paso 3.8).
   - Jamás se carga el corpus completo de notas en el prompt; el prefijo estático (`StaticSystemPrefix`) conserva su `prefix_sha256` invariante entre turnos.

---

## 3. Contratos Principales (`miku-memory::markdown_vault`)

| Tipo / Método | Responsabilidad |
| :--- | :--- |
| `MarkdownNoteMetadata` | Metadatos de nota indexada (`relative_path`, `canonical_path`, `title`, `tags`, `file_sha256`, `chunk_ids`, `updated_at_ms`). |
| `VaultSyncReport` | Contadores verificables de sincronización (`scanned_files`, `indexed_new_files`, `reindexed_modified_files`, `skipped_unchanged_files`, `deleted_stale_files`, `indexed_session_records`, `total_fts5_documents`). |
| `MarkdownMemoryVault::write_markdown_note` | Valida `Capability::FsWrite`, escribe `.md` legible en disco e indexa fragmentos en `memory_fts5`. |
| `MarkdownMemoryVault::sync_vault_directory` | Escanea `.md`, reindexa solo hashes SHA-256 modificados y purga notas eliminadas. |
| `MarkdownMemoryVault::rebuild_fts5_index_from_sources` | Reconstruye íntegramente `memory_fts5` desde los `.md` en disco y las sesiones SQLite. |
| `MarkdownMemoryVault::retrieve_on_demand_within_budget` | Inyecta bajo demanda solo los fragmentos relevantes respetando `max_budget_tokens`. |

## 4. Cobertura TDD (Paso 3.9)

- `LEDGER-3.9-1`: Indexación de 500 notas Markdown + 30 registros de sesión con ranking BM25 y búsqueda `< 10.0 ms` (con calentamiento + 25 muestras).
- `LEDGER-3.9-2`: Sincronización incremental SHA-256 al editar un `.md` (`0` reindexados en archivos intactos), purga de notas eliminadas y reconstrucción completa del índice desde `.md`.
- `LEDGER-3.9-4`: Bloqueo estricto de lecturas/búsquedas cuando Gatekeeper deniega `Capability::FsRead`.
- `LEDGER-3.9-5`: Recuperación bajo demanda respetando el presupuesto de tokens sin inyectar el corpus completo.
