# F-07 — Host y Cliente MCP (`miku-mcp`)

- **Estado:**
  - **Micro-paso 3.3:** VERIFICADO (`miku-mcp` Host MCP en loopback/stdio con intercepción Gatekeeper)
  - **Micro-paso 3.4:** VERIFICADO (`miku-mcp` Cliente MCP para servidores externos configurados en `.miku.toml`)
- **Crate principal:** `miku/crates/miku-mcp`
- **Dependencias internas:** `miku-protocol`, `miku-core`, `miku-gatekeeper`, `miku-agent`
- **ADR asociado:** `ADR-004` (*SDK MCP en Rust (`rmcp` vs implementación JSON-RPC 2.0 nativa)*)
- **Presupuestos y garantías:**
  - Despacho MCP `tools/call` `< 5.0 ms` (`p50 = 0.1360 ms`, `p95 = 0.4297 ms`).
  - Timeout no bloqueante: cancelación asíncrona en `< 100 ms` sin bloquear el reactor tokio.
  - En reposo: `0` procesos MCP externos activos tras vencer `idle_ttl_ms`.
  - Cero procesos huérfanos tras activación de Kill Switch o apagado limpio (`shutdown`).

## 1. Alcance del Micro-paso 3.3 (Host MCP)

El Micro-paso 3.3 implementó el **Host MCP de Miku** dentro de `crates/miku-mcp`, permitiendo que clientes MCP locales (Cursor, Claude Code, etc.) descubran e invoquen herramientas registradas en Miku bajo supervisión estricta de `miku-gatekeeper` y auditoría encadenada SHA-256 (`TamperEvidentAuditLog`).

- **Transporte:** JSON-RPC 2.0 (`2024-11-05`) sobre TCP loopback (`127.0.0.1` / `::1`) y líneas stdio (`handle_stdio_line`).
- **Seguridad:** Verificación estricta de loopback (`NonLoopbackBindForbidden` si se intenta enlazar a `0.0.0.0` o IPs de red).
- **Control de acceso:** Token en tiempo constante (`constant_time_token_eq`) y evaluación deny-by-default en `GatekeeperEngine`.

---

## 2. Alcance del Micro-paso 3.4 (Cliente MCP Externo)

El Micro-paso 3.4 implementa el **Cliente MCP de producción de Miku** (`ExternalMcpClientManager` y `ExternalMcpServerConfig`), permitiendo consumir servidores MCP externos declarados en `.miku.toml` con las siguientes garantías:

1. **Declaración en `.miku.toml`:**
   - Sección `[mcp_servers.<name>]` con campos `command`, `args`, `env`, `timeout_ms` (por defecto `5,000 ms`) e `idle_ttl_ms` (por defecto `30,000 ms`).
2. **Ciclo de vida bajo demanda:**
   - Los procesos MCP hijos **no se inician al arrancar Miku** (`auto_start = false` por defecto).
   - Solo se inician cuando una sesión adquiere el servidor (`acquire_session`) o invoca una herramienta (`call_tool`).
   - Se mantiene la cuenta de sesiones activas. Cuando todas las sesiones se liberan (`release_session`) y transcurre `idle_ttl_ms` de inactividad, `reap_idle_servers` finaliza el proceso hijo (`kill` + `wait`), liberando todos los recursos (`0` procesos en reposo).
3. **Control de capacidades (Gatekeeper Deny-by-Default):**
   - Antes de enviar cualquier mensaje `tools/call` al servidor externo, el cliente evalúa la solicitud en `GatekeeperEngine::evaluate_request`.
   - Si el veredicto es `Deny` o `AskPending`:
     - **Se envían 0 llamadas al servidor externo.**
     - Se registra el evento de denegación en `TamperEvidentAuditLog`.
     - Devuelve error tipado `McpClientError::GatekeeperDenied`.
4. **Protección de Timeout no bloqueante:**
   - La llamada está protegida por `tokio::time::timeout(Duration::from_millis(timeout_ms), ...)`.
   - Si el servidor tarda más de lo configurado, la petición se aborta y retorna `McpClientError::Timeout` sin bloquear el hilo reactor del daemon.
5. **Apagado Limpio y Kill Switch:**
   - Al activar el Kill Switch (`trip_kill_switch`) o apagar Miku (`shutdown`), todos los procesos hijos se cierran inmediatamente con `child.kill().await` y `child.wait().await`.
   - Se garantiza `0` procesos huérfanos.
6. **Resiliencia de protocolo y redacción de secretos:**
   - Respuestas corruptas o desconexiones generan errores tipados (`ProtocolError`, `TransportError`) sin pánicos.
   - Los mensajes de error y logs **nunca filtran** valores de variables de entorno, claves de API ni tokens sensibles.
   - Una sesión posterior reinicia y recupera el servidor de forma transparente.

## 3. Validación de `ADR-004`: Peso de Dependencias

- **Terceros en `Cargo.lock`:** Se mantiene exactamente en **32 paquetes** de terceros (`0` copyleft), auditados por `miku-cli::license_audit`.
- **Zero New External Crates:** `miku-mcp` utiliza exclusivamente `tokio` (con feature `process`, ya presente en el ecosistema), `serde`, `serde_json`, `toml` (ya presente en el workspace) y crates internos (`miku-protocol`, `miku-core`, `miku-gatekeeper`, `miku-agent`), evitando las 60+ dependencias transitivas de `rmcp`.
