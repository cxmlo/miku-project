# F-23 · Historial Buscable de Sesiones y Buscador Instantáneo `Ctrl+K` en la Island

## 1. Objetivo Arquitectónico

Indexar el historial de sesiones (`sessions` y `conversation_turns`) junto con las notas Markdown de largo plazo en el motor léxico SQLite FTS5 (`miku-storage`) y exponer un buscador instantáneo en la Island activado mediante el atajo `Ctrl+K` sobre IPC tipado JSON-RPC 2.0, con latencia local `< 10.0 ms` y resultados acotados.

---

## 2. Flujo de Extremo a Extremo (`Ctrl+K` → IPC → FTS5 → Island)

1. **Activación por atajo (`Ctrl+K`):**
   - `IslandMemorySearchController::trigger_ctrl_k()` abre la paleta de búsqueda en la Island (`palette_open = true`) y `close_on_escape()` la cierra limpiamente al pulsar `Escape`.
2. **Petición IPC tipada (`IslandMemorySearchIpcRequest`):**
   - La UI de la Island envía una trama JSON-RPC 2.0 (`v = 1`, `origin = "https://miku.local/*"`, `shortcut = "Ctrl+K"`, `raw_query`, `filter`, `limit`, `agent_id`, `timestamp_ms`).
   - El controlador valida el origen (`validate_island_origin`), el tamaño de trama (`<= 16 KiB`, sin bytes nulos) y la versión del protocolo antes de ejecutar cualquier consulta.
3. **Sanitización y Ranking BM25 (`sanitize_fts5_query` + `search_fts5`):**
   - La consulta pasa obligatoriamente por `sanitize_fts5_query`, que elimina comentarios SQL (`--`, `/*`), separadores (`;`), operadores reservados (`AND`, `OR`, `NOT`, `NEAR`, `DROP`, `SELECT`, `DELETE`) y caracteres no léxicos. Jamás se concatena texto crudo del usuario en expresiones SQL o FTS5.
   - `SingleThreadStoragePool::search_fts5` calcula el score BM25 ponderado (`title * 3.0 + tags * 2.0 + body * 1.0` + bonificación por cobertura de términos distintos) escaneando tokens sobre un buffer reutilizable sin asignaciones por palabra.
4. **Autorización Gatekeeper y Acotación de Resultados (`IslandMemorySearchIpcResponse`):**
   - Cada nota candidata se valida contra `GatekeeperEngine` (`Capability::FsRead`).
   - El número de resultados devueltos a la Island se acota estrictamente mediante `limit.clamp(1, HARD_MAX_ISLAND_SEARCH_RESULTS)` (`DEFAULT = 10`, `MAX = 25`), indicando `truncated_to_limit = true` y `total_indexed_corpus_docs` sin serializar jamás el corpus completo de 500+ documentos por IPC.
   - Todo título, ruta y snippet se escapa para renderizado seguro en DOM (`escape_text_for_island_dom`) y pasa por `redact_sensitive_text` para impedir filtración de secretos o rutas sensibles del sistema operativo.

---

## 3. Presupuesto de Rendimiento y Verificación

- **Presupuesto de latencia:** Búsqueda local FTS5 `< 10.0 ms` sobre un corpus de 500 notas Markdown + 30 registros de sesión.
- **Método de medición (`LEDGER-3.9-1`):** 5 iteraciones de calentamiento seguidas de 25 muestras medidas con cálculo de mediana (`p50`) y percentil 95 (`p95`).
- **Cobertura TDD:**
  - `LEDGER-3.9-1`: Benchmark estadístico `< 10.0 ms` con 500 notas + historial de sesiones.
  - `LEDGER-3.9-3`: Ranking BM25 multi-término, consultas vacías/malformadas y resistencia a inyección FTS5/SQL.
  - `LEDGER-3.9-6`: Flujo completo `Ctrl+K` → IPC JSON → búsqueda FTS5 filtrada (`All`, `MarkdownOnly`, `SessionsOnly`) → respuesta acotada (`<= 25` ítems) y rechazo de orígenes no confiables.
